Executive answer

Extend the existing web-design branch and PR #18; do not create a competing suite. The final package adds nine standalone skills whose triggers form a useful chain from art direction through implementation, audit, framework engineering, and browser evidence.

9

new skill packages

Five already staged in PR #18, plus React performance, React composition, design-system engineering, and official Angular guidance.

6

coordinated upgrades

Existing skills now route specialist work cleanly and use WCAG 2.2 instead of duplicating stale instructions.

5

rejected or deferred

Overlap, license portability, narrow product coupling, and wrong-audience workflows were treated as costs, not bonuses.

Core recommendation: merge this modular set after one independent approval. Keep generic architecture, API, security, test, performance, responsiveness, and shipping work with the mature skills that already own those triggers.

Duplicates were replaced in place

web-accessibility → 2.0.0

The prior package was WCAG 2.1-era, incomplete, and advised application-menu roles for ordinary site navigation. The replacement targets WCAG 2.2, native semantics first, complete widget behavior, state matrices, manual keyboard and assistive-technology checks, and criterion-mapped evidence. Automated scores are explicitly insufficient for conformance.

frontend-ui-engineering → 1.1.0

The umbrella skill remains the implementation router. It now discovers project context first, sends art direction, design systems, React, audit, accessibility, and browser work to their specialist packages, removes a broken reference, and replaces brittle universal thresholds with responsibility- and content-driven checks.

Audit and visual implementation

web-design-guidelines and image-to-code now cross-reference the design-system and accessibility owners. Their versions increase because routing and reference behavior changed.

Browser ownership

playwright-cli owns pinned CLI commands and sensitive-session boundaries; playwright owns tool selection and routes CLI-specific requests. This keeps both useful without two conflicting command manuals.

Current standards baseline

  • WCAG 2.2 is the current W3C Recommendation; the upgraded skill uses its A/AA criteria and does not turn a scanner score into a conformance claim.
  • The ARIA Authoring Practices Guide is informative widget guidance. Native HTML remains the first choice.
  • Core Web Vitals defines “good” field thresholds at the 75th percentile: LCP ≤ 2.5 s, INP ≤ 200 ms, and CLS ≤ 0.1. Performance claims still require like-for-like measurement.
  • DTCG 2025.10 is a stable Final Community Group Report for token interchange, accurately described as a community specification rather than a W3C Recommendation.
  • Storybook UI tests can reuse stories as component states; Playwright visual comparisons require stable rendering environments and reviewed baseline changes.

Release gate

Schema

Required frontmatter, directory/name agreement, SemVer, triggers, required body sections, and concrete verification.

Integrity

Every related skill resolves, every local Markdown link exists, and supporting files are explicitly routed.

Provenance

Vendored sets are compared to immutable upstream revisions; license files and adaptation notes travel with each package.

Safety

No credentials or unowned absolute paths; runtime downloads do not control instruction bodies.

Rendering

This report is inspected at desktop and mobile sizes for overflow, readability, focus, and dark-mode integrity.

Governance

Issues #17, #19, #20, and #21 feed PR #18. One independent approval is required before merge.
